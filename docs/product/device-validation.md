# 휴대폰 검증 절차

코어 테스트, 에뮬레이터, APNs 접수와 물리 휴대폰의 첫 소리를 따로 기록한다. 최종 제품 요구는 내비 앱 사용·화면 잠금 중 받은 원음이 사용자의 추가 조작 없이 재생되는 것이다. 알림 도착이나 서버 접수는 이 요구의 통과 근거가 아니다.

## 실행 전 조건

각 휴대폰의 모델·OS, 앱 커밋·APK/앱 빌드, 내비 앱 이름·버전, 배터리 절전 상태, 네트워크를 기록한다. 검증 중 절전 예외를 강제로 설정하지 않는다. 송신자와 수신자는 별도 회원으로 참여하며 실제 마이크로 식별 가능한 짧은 문장을 녹음한다. 로그·캡처·공유 기록에는 bearer, 초대 secret, 임시 push token, 서명 키를 넣지 않는다.

현재 Node 서버는 Mac의 loopback에만 열린다. 휴대폰의 `127.0.0.1`은 Mac 주소가 아니다. Android 개발 테스트는 명시적으로 선택한 테스트 기기의 `adb reverse tcp:4180 tcp:4180` 연결을 사용할 수 있으며 연결·해제와 USB 유지 여부를 기록한다. iPhone 실증에는 해당 기기에서 접근할 수 있는 신뢰된 HTTPS 원음 서버와 실제 APNs 경로가 필요하다. 공개 배포·터널·TLS 검증 우회를 이 절차에서 자동 구성하지 않는다.

iPhone에는 전체 Xcode/iOS SDK, 적절한 개발 서명과 PushToTalk·Push Notifications capability, 실제 APNs 자격증명, 연결 iPhone이 필요하다. macOS SwiftPM 테스트는 이 조건을 대신하지 않는다. Android의 디버그 빌드는 실제 기기 설치·녹음·재생을 대신하지 않는다.

## 기록할 검사

1. **전경 원음:** 실제 1초·15초 녹음, 중지·취소·권한 거절을 검사한다. 취소한 음성이 서버에 없어야 하며, 전송한 WAV는 실제 표본 수와 같은 길이여야 한다. 서로 다른 참여자가 발신자와 원래 소리를 확인한다.
2. **명시적 수신·중지:** 수신자가 자동 수신을 직접 시작한 뒤 새 원음을 보낸다. 실제 첫 소리 시각을 기록한다. 수신을 중지하고 다시 보내면 자동 소리가 없어야 한다. 자기 원음·중복·30초 지난 이력은 자동 재생하면 안 된다.
3. **내비 전경·화면 잠금:** 동일한 빌드로 내비를 켠 상태와 화면 잠금 상태를 각각 검사한다. 송신·수신/푸시 접수·실제 첫 소리 시각을 구분해 남긴다. 받는 사람이 화면을 열거나 알림을 누르지 않아야 한다.
4. **장시간 무음:** 수신 세션만 켠 채 소리를 재생하지 않고 각각 15분, 30분을 유지한다. 이후 새 원음을 보내고 처음 소리가 나는지 검사한다. 무음 루프·테스트 heartbeat 음성·사용자 수동 재활성화로 생존을 유지하지 않는다. 두 구간은 별도 결과다.
5. **수명주기:** 녹음·다운로드·재생 중 취소, 통화/다른 오디오의 중단, 방 종료·탈퇴·만료, 네트워크 복구를 검사한다. 중지·이전 채널·오래된 메시지가 뒤늦게 재생되지 않아야 한다. iPhone 시스템 채널 복원과 Android 서비스 종료 후 상태도 관찰한다.

## 결과 양식

| 필드 | 기록 |
|---|---|
| 대상·버전 | 모델, OS, 앱 commit/build/hash, 내비 버전 |
| 조건 | 전경/내비/잠금/15분 무음/30분 무음, 절전·네트워크·연결 방식 |
| 시각 | 시작, 송신, 서버 접수, push/수신, 실제 첫 소리 |
| 관찰 | 실제 청취와 발신 문장, 사용자 조작 유무, 중지 후 소리 유무 |
| 결과 | PASS / FAIL / BLOCKED / NOT RUN, 근거 파일과 다음 재개 조건 |

지연의 허용 상한은 아직 정하지 않았다. 실제 측정값을 먼저 기록하고, 첫 소리가 났다는 결과를 지연 기준까지 통과한 것으로 확장하지 않는다. 전체 상태는 [검증표](platform-validation.md)에 반영한다.
