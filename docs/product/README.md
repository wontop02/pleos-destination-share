# 프로토타입 개발

2026-11-04 사용자가 단계마다 멈추지 말고 개발을 계속 진행하라고 지시했다. 앱 개발을 재개하고 아래 범위에서 이슈를 구현·검증·병합한다. 보안 권한 확대, 계정 가입, 결제, 공개 배포는 포함하지 않는다.

## 기존 고정 묶음과 현재 상태

1. **#6 첫 실행본:** 공유방, 목적지 전달, 최대 15초 원음과 실제 로컬 서버·웹 화면을 [PR #9](https://github.com/wontop02/pleos-destination-share/pull/9)로 병합했다. 차량 앱도 이 인증·목적지 API를 사용한다.
2. **#7 Android:** [Draft PR #10](https://github.com/wontop02/pleos-destination-share/pull/10). Kotlin 검사·전체 앱 빌드·lint·에뮬레이터 UI는 실행했다. 실제 마이크와 Galaxy의 잠금·내비 사용·15/30분 무음 후 첫 소리는 BLOCKED다. `main` 미병합이다.
3. **#8 iPhone:** [Draft PR #11](https://github.com/wontop02/pleos-destination-share/pull/11). Xcode 27.2/iOS SDK 27.2 시뮬레이터 빌드·UI 복원을 실행했다. 실제 마이크·청취·PTT 서명/APNs·잠금·내비·15/30분 후 첫 소리는 BLOCKED다. `main` 미병합이다.

계정·기기 부족으로 한 이슈가 막히면 이유와 재개 조건을 남기고 독립적인 다음 작업을 진행한다. 단계마다 사용자 재지시를 기다리지 않는다. 앱 전체의 필수 휴대폰 수신 조건을 웹 시연이나 알림 도착만으로 완료 처리하지 않는다.

2026-11-04 묶음은 #6, #7, #8로 고정한 그대로 보존한다. 새 기능을 이 묶음에 추가하지 않는다.

## 별도 승인: Pleos 차량 우선

2026-11-05 사용자가 “Pleos 차량 앱부터 ㄱㄱ. 기존처럼 이슈 → be/ 브랜치 → PR로 진행하고, 순정 내비 목적지 공유·변경부터 검증해줘.”라고 지시했다. 이 실행 묶음은 [#12](https://github.com/wontop02/pleos-destination-share/issues/12) 하나다. [차량 앱](../../prototype/vehicle/README.md)은 `main`의 공통 서버를 사용하며 미병합 휴대폰 앱과 독립적으로 진행한다.

대표의 현재 순정 목적지 조회·명시적 공유, 다른 회원의 최신 목적지 수신·명시적 적용, 실제 순정 목적지 후속 조회의 일치를 검사한다. #12의 범위에는 자동 공유·자동 따르기, AI/STT/TTS, 차량 원음/PTT, 티맵·카카오 연동이 없었다. 기존 v1의 이름·좌표 요청/응답을 보존하고 optional Pleos 메타데이터, 명시적 공유값 삭제, 선택적 버전 경합 검사만 확장한다. 계약은 [차량 문서](../../prototype/vehicle/README.md#목적지-api-하위-호환-확장)를 따른다.

공식 Pleos 환경 두 대의 실제 내비 실증과 별도 verifier가 필수다. 앱·서버 테스트, 일반 Android, 가짜 gateway, SDK 호출 전송은 실증의 대체 증거가 아니다. 미확인 조건은 [검증 기록](../../prototype/vehicle/evidence/verification.md)에 남기며 Draft/BLOCKED를 유지한다. 보안 권한 확대, 가입·결제, 공개 배포는 승인 범위에 포함하지 않는다.

## 별도 승인: 앱 복귀 없는 자동 동행

2026-11-05 사용자가 자동 따르기를 한 번 켜면 순정 내비 화면에서 목적지 자동 공유·변경·실제 반영 확인까지 끝내도록 지시했다. 새 실행 묶음은 [#14](https://github.com/wontop02/pleos-destination-share/issues/14) 하나이며 #12/PR #13의 main `7d9dcc053c8dfe2b8ce1f22fef3c17b9c8c54856`을 기준으로 한다. 앞선 #6/#7/#8·#12 묶음은 보존한다.

기본 꺼짐, 대표/참여자의 별도 명시 동의, Activity와 독립된 specialUse FGS, 진행 알림과 중지, 최신 버전 자동 적용·실제 조회 strict match를 구현한다. 같은 인증 API·암호화 저장을 사용하며 서버 변경은 없다. 역할별 제어·수명·권한·회귀·두 공식 차량 15분 연속 실증 조건은 [자동 동행 계약](vehicle-auto-follow.md)을 따른다. 재진입 0회·10분 이후 변경·중지 후 요청 0회·정확한 APK/source 해시를 직접 확인해야 AC5를 통과한다. 실제 플랫폼/SDK 문제로 실패하면 Draft/BLOCKED이며 기준을 낮추지 않는다.

동결 3 실제 실행에서 두 공식 에뮬레이터가 908.721초·55쌍의 관찰 동안 순정 내비 전경과 같은 PID·foreground 서비스 epoch를 유지했고 Activity 재진입은 A/B 0회였다. 10분 이후를 포함한 세 변경 각각 B 새 요청 한 번과 실제 native strict match를 확인했다. 상태 우선 알림 제목은 실제 대비 14.3904483:1로 표시됐다. 실제 알림 중지 후 새 A 변경 작업 완료 뒤 81.347894375초 동안 B 새 요청·재진입은 0회이고 기존 목적지를 유지했다. [시각·버전·해시와 실행 기록](../../prototype/vehicle/evidence/automatic-session/verification.md)은 이 총괄 관찰과 동결 2의 907.743초 기능 실증·독립 F1 전체 FAIL을 구분한다. 최종 독립 판정과 병합 상태는 [PR #15](https://github.com/wontop02/pleos-destination-share/pull/15)를 참조한다. 실차·탐색 완료 이벤트·specialUse 배포 심사 승인은 검증하지 않았다.

## 별도 승인: 버튼 기반 목적지 변경 제안

2026-11-05 승인한 [#17](https://github.com/wontop02/pleos-destination-share/issues/17)은 #14/PR #15의 main `875c353f9918981571908bda7e47b800ceff7897`을 기준으로 한다. 현재 회원 누구나 두 공개 순정 POI 중 하나와 이유를 제안하고 전원 수락 뒤 양쪽 차량에 반영한다. 대기·거절·120초 미응답/만료·무효화는 기존 목적지를 유지한다. 자동 동행이 꺼져 있어도 해당 버튼 동의와 작업의 제한된 FGS 수명으로 실제 후속 조회를 계속한다. [제안 API·UI·수명·검증 계약](vehicle-proposals.md)을 따른다. 지도 공백 #16은 사용자 결정으로 복구를 보류하며 이번 범위에 포함하지 않는다.

Builder의 HTTP/JVM 검사와 빌드/lint는 실제 두 전용 Pleos 차량 AC5 및 별도 verifier를 대체하지 않는다. 총괄이 새 4186 서버·APK 해시·실제 native match와 중복/미수락 보호를 검증한 뒤 완료를 판단한다. 기존 실행 기록은 보존한다.

## 현재 결정

- 녹음 후 전송하는 짧은 원음을 우선한다. 실시간 통화·음성 합성은 현재 범위가 아니다.
- 첫 공통 형식은 PCM16 mono 16kHz WAV다. 브라우저·네이티브 간 검증을 단순화하며 압축 코덱은 후속 결정이다.
- 자동 재생은 사용자가 선택한 수신 세션과 신선한 메시지에만 적용한다. 보관 이력은 수동 재생한다.
- 기존 하네스의 GitHub 병합 검사를 총괄과 독립 verifier가 수행한다. 추가 어댑터·자동 게이트는 앱 개발을 막지 않는다.
- 로컬 큐 프로그램의 고정 정책은 여전히 harness/docs 전용이다. 앱 승인으로 기존 체크포인트 정책을 임의 변경하지 않으며 제품 이슈는 현재 채팅이 직접 관리한다.

화면 기준은 [DESIGN.md](../../DESIGN.md), 공통 용어는 [GLOSSARY.md](../../GLOSSARY.md), 구현·검증 절차는 [하네스 운영 규칙](../harness/README.md)을 따른다. 상위 폴더의 이전 계획과 시제품은 참고 자료로 보존한다.
