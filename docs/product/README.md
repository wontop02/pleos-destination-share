# 프로토타입 개발

2026-11-04 사용자가 단계마다 멈추지 말고 개발을 계속 진행하라고 지시했다. 앱 개발을 재개하고 아래 범위에서 이슈를 구현·검증·병합한다. 보안 권한 확대, 계정 가입, 결제, 공개 배포는 포함하지 않는다.

## 구현 순서

1. **#6 첫 실행본:** 공유방, 목적지 전달, 최대 15초 원음 녹음·전송·수신, 실제 로컬 서버와 웹 화면. 네이티브 앱의 인증·음성 API 기반을 만든다.
2. **#7 Android:** Kotlin 네이티브 앱의 명시적 수신 시작·중지, 오디오 서비스와 원음 송수신을 구현한다. SDK 빌드와 기종별 실제 잠금·내비 사용·15/30분 무음 후 첫 소리를 구분해 검증한다.
3. **#8 iPhone:** Swift·PushToTalk 채널, APNs 수신과 시스템 오디오 활성화 후 원음 재생을 구현한다. Xcode 전체 앱, 서명/PTT capability와 iPhone 실기기가 없으면 실제 빌드·배경 검증은 보류한다.

계정·기기 부족으로 한 이슈가 막히면 이유와 재개 조건을 남기고 독립적인 다음 작업을 진행한다. 단계마다 사용자 재지시를 기다리지 않는다. 앱 전체의 필수 휴대폰 수신 조건을 웹 시연이나 알림 도착만으로 완료 처리하지 않는다.

이번 묶음의 제품 이슈는 #6, #7, #8로 고정한다. 새 기능을 발견하면 이 묶음에 몰래 추가하지 않는다. 자율 진행 승인은 이 범위 안의 구현·검증·정상 병합이며 보안 권한 확대나 유료 서비스 가입 승인이 아니다.

## 현재 결정

- 녹음 후 전송하는 짧은 원음을 우선한다. 실시간 통화·음성 합성은 현재 범위가 아니다.
- 첫 공통 형식은 PCM16 mono 16kHz WAV다. 브라우저·네이티브 간 검증을 단순화하며 압축 코덱은 후속 결정이다.
- 자동 재생은 사용자가 선택한 수신 세션과 신선한 메시지에만 적용한다. 보관 이력은 수동 재생한다.
- 기존 하네스의 GitHub 병합 검사를 총괄과 독립 verifier가 수행한다. 추가 어댑터·자동 게이트는 앱 개발을 막지 않는다.
- 로컬 큐 프로그램의 고정 정책은 여전히 harness/docs 전용이다. 앱 승인으로 기존 체크포인트 정책을 임의 변경하지 않으며 제품 이슈는 현재 채팅이 직접 관리한다.

화면 기준은 [DESIGN.md](../../DESIGN.md), 공통 용어는 [GLOSSARY.md](../../GLOSSARY.md), 구현·검증 절차는 [하네스 운영 규칙](../harness/README.md)을 따른다. 상위 폴더의 이전 계획과 시제품은 참고 자료로 보존한다.
