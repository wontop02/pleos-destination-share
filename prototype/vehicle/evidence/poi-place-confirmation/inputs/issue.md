## 목표

일반 Pleos 장소를 제안·수락한 뒤, 검색/저장 지점과 차량의 실제 안내 지점이 다르다는 이유로 확인이 실패하는 문제를 해결한다. 사용자가 선택한 장소의 식별 정보와 차량별 실제 안내 지점을 구분하고, 확인한 사실에 맞는 완료 상태를 표시한다. 기존 좌표 기반 목적지의 엄격한 검증은 유지한다.

## 동작 계약

- 기존/모드 누락 payload와 현재 순정 목적지 공유는 좌표·이름·POI ID·nullable sub-ID·provider의 기존 strict 기준을 유지한다.
- 일반 장소 선택은 공식 NaviHelper의 실제 북마크 원본에서 구성하며, 선택한 장소와 안내 지점을 명시적으로 구분한다. 새로운 장소 확인 모드는 공급자·POI ID·sub-ID·이름·지원 출처와 현재 작업/SDK epoch를 검사한다. POI ID 단독 확인, 허위 ID, 외부 place ID 재사용, 거리 허용치 확대, 실제 관측값으로 기대 지점을 덮는 self-match를 사용하지 않는다.
- 새 모드가 확인하는 것은 '선택한 장소로 목적지가 설정됨'이다. 입력 좌표 일치, 같은 진입 지점/경로 또는 경로 탐색 완료까지 확인했다는 표시를 하지 않는다. 원본 이름·주소·좌표·식별 정보와 실제 후속 안내 지점을 각각 보존한다. 문서 근거와 현재 버전에 한정한 지원 조건을 명시한다.
- 선택/확인 의미는 제안·공유 snapshot·수락 처리까지 손실 없이 전달되고, 알 수 없는 모드·출처·불완전 metadata는 거부한다. 전원 수락, 버전/기한·중복·재연결·중지·cold-resume 보호를 유지한다. 대기·거절·만료 중 경로를 요청하지 않는다.
- 최소 제품 연결은 '저장한 장소 불러오기 → 명시 선택 → 기존 변경 제안'이다. 일반 장소 UI는 카테고리 고정 fixture를 늘리지 않는다. 새 키워드 검색 결과 callback이나 공급자 지원을 꾸미지 않는다. 북마크 전체를 서버/로그로 보내지 않고 선택한 후보만 명시적인 제안 때 전달한다.
- UI의 기존 카드·20sp 본문·56dp 버튼·세로 스크롤을 재사용하고 DESIGN.md에 새 상태를 기록한다. 장소 확인과 좌표 일치 확인을 사용자가 구분할 수 있게 표시한다.

## 완료 조건

- AC1: #19 실제 카페 입력/후속 응답(약 51m 차이)을 최소 재현으로 고정하고, 관련 실제 production seam을 검사하는 RED/GREEN 회귀를 남긴다. 일반 장소 기대와 안내 지점의 모델·불변 조건·공식 근거를 문서화한다. 기존 exact 모드에서 같은 ID/다른 좌표가 계속 불일치여야 한다.
- AC2: 신규 장소 확인은 완전한 식별 정보·유효한 실제 지점·fresh SDK/요청 수명에서만 성공한다. 이름/ID/provider/sub-ID 불일치·누락·오류·시간 초과·이전 epoch/중지/다른 방/오래된 수락은 성공이나 새 요청이 되지 않는 회귀가 통과한다. onRouteStarted/SDK 반환만으로 완료하지 않는다. 기존 동의·120초 만료·원래 확인 기한·replay 보호를 유지한다.
- AC3: 저장한 실제 장소를 불러와 선택·제안할 수 있다. 로딩/빈 목록/실패/잘못된 metadata/취소/지연 응답/SDK 재연결/방·회원 교체 시 후보 수명과 중복 요청을 처리한다. 원본 선택을 보존하며 수락 후 관측값을 원본으로 바꾸지 않는다. 새 모드와 모드 없는 이전 HTTP payload의 호환성과 알 수 없는 모드 거부를 검사한다.
- AC4: 자동 동행에서도 신규 장소를 확인한 뒤 실제 안내 좌표 차이가 불필요한 재공유·재적용 루프나 잘못된 완료 표시를 만들지 않는다. 기존 native exact 목적지 공유/수동 적용/제안·수락·거절의 회귀가 통과한다. Node 전체·core/app JVM·app build/lint와 필요한 driver 검사를 실제 명령/종료 코드로 남긴다.
- AC5: 전용 가상 차량 두 대에서 실제 제품 APK와 일반 장소(카페 및 다른 유형 1개 이상)의 양방향 제안·거절·전원 수락을 실행한다. 미수락 중 SDK 경로 요청 0회, 수락 후 독립 실제 native 조회·완전한 장소 식별 일치·확인 종류 표시와 45초 이후에도 공유 revision 안정/반복 요청 방지를 기록한다. 기존 exact 방식도 실제 1회 회귀 검증한다. 입력/설치 해시·정확한 base/head·별도 context verifier PASS가 있어야 완료하며 미구현/부분 검증을 완료로 표현하지 않는다.
