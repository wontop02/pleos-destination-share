길맞춤의 핵심 흐름을 사용자가 실제 목적지를 정한 뒤 다른 차량에 변경 요청을 알리는 방식으로 바꾼다. 장소명·업종의 실제 검색 결과를 쓰며 ☆ 저장 목록이나 음성 초안은 선행 조건이 아니다.

2026-11-10 이 채팅의 사용자 지시: “관련 장소로 해야지. 그리고 흐름이 ~어디 가자 보다는 목적지 변경 정한 다음에 다른 차들한테 알리는 거야. 음성 꼭 없어도 되고. 목적지 변경 요청 알림이 뜨면 될 것 같은데.”
사용자 후속 답변: 관련 장소는 “장소명·업종으로 검색한 실제 장소”.
사용자 후속 답변: 수신 방식은 “각 차량이 수락하면 변경”. 각 수신 차량의 명시 수락 후 그 차량만 반영하며 다른 회원의 수락을 기다리지 않는다. 전원 수락을 기다리는 기존 제안 흐름을 새 주 흐름에 적용하지 않는다.

## 완료 조건

- AC1 실제 장소 검색: 길맞춤의 기본 목적지 변경 화면에서 장소명 또는 업종을 입력하고 공개 NaviHelper SearchPlace를 통해 실제 순정 검색 결과를 보여 준다. 앞선 #19에서 확인한 Activity 전경 조건을 지킨다. 순정 검색 결과에서 사용자가 장소를 정하고 목적지를 설정한 뒤 앱에 돌아와 실제 현재 목적지의 이름·주소를 조회/확인한다. ☆ 저장, 하드코딩 장소, 음성·LLM·새 외부 검색 계정/키가 필요하지 않다. SDK 화면 요청 접수만으로 결과 표시/선택 성공을 주장하지 않는다.
- AC2 확정 후 알림: 발신자는 실제 순정 목적지를 새로 조회하여 확인한 뒤 “다른 차량에 변경 요청 보내기”를 명시 선택한다. 조회 전·조회 실패·오래된 화면·검색 화면 이탈·방/회원 변경 시 발신하지 않는다. 목적지를 정한 발신 차량에 같은 경로를 다시 요청하지 않는다. 앱명과 주 흐름은 “길맞춤”, 음성은 필수/첫 단계가 아니다.
- AC3 개별 수락: 다른 유효 회원에게 이름·주소·발신 차량과 변경 요청을 표시한다. 수신만으로 내비를 바꾸지 않고 각 수신자의 명시 수락 후 해당 차량만 경로를 1회 요청하고 실제 후속 목적지 확인을 한다. 다른 회원의 무응답/거절이 수락 차량을 막지 않는다. 전송·수락·SDK 요청·실제 목적지 확인을 분리한다. 기존 전원 합의 API·기존 HTTP/SSE 클라이언트 회귀는 유지하거나 명확한 호환 경계를 둔다.
- AC4 알림과 수명: 사용자가 시작한 변경 요청 수신 세션은 순정 내비 전경에서도 요청을 받아 실제 Android 알림으로 보여 준다. 알림을 눌러 현재 요청을 확인·수락/거절할 수 있다. 명시 중지·탈퇴·인증 종료·만료·새 요청 교체는 이전 알림/수락 권한을 무효화한다. cold 재연결의 과거 요청, 중복 SSE/응답/탭은 경로를 자동 재생하지 않는다. 기존 자동 동행이 새 개별 수락을 우회하지 못한다. 초대·인증 비밀·마이크·원음을 알림/로그에 노출하지 않는다.
- AC5 검증·보존: 관련 Node/JVM 회귀와 실제 APK 빌드/lint를 통과한다. 실제 인증 HTTP/SSE에서 3명 이상의 개별 수락/거절·동시/역순/재시도·만료·권한 경계를 확인한다. 별도 승인된 Pleos 두 AVD에서 실제 이름/업종 검색 결과, 검색→실제 목적지 설정→명시 발신→상대 순정 내비 전경 알림→수락 전 새 경로 0회→수락 후 1회와 fresh native 확인을 동일 빌드로 검증한다. 기존 4190/4192 서버·방·초안·APK 증거는 보존하고 별도 서버/로컬 상태로 실행한다. 새 공개 배포나 release 제출 완료는 주장하지 않는다.

## 검증

- 구현은 builder 계약의 별도 문맥, 검증은 수정 없는 verifier 계약의 별도 문맥으로 순차 배정한다.
- 현재 설치·실행 중인 두 전용 AVD(ADB5041, emulator-5570/5572, user10)를 사용하되 사용자 방을 삭제하지 않는다. 새 APK는 빌드/정적·자동 검사 후에만 설치한다. 필요 시 원래 APK·암호화 인증을 보존하는 복구 경로를 먼저 기록한다.
- 실제 SDK/순정 화면을 사용한다. 공개 SDK/정상 제품 UI·testOnly self-targeted 진단만 사용하고 vendor private API·DB·특권·인식 결과 주입을 사용하지 않는다.
- 필수 실제 화면·알림·마이크 없는 흐름·요청 횟수·후속 목적지 조회·소스/APK SHA와 실패를 선별 기록한다.
- 완료는 정확한 base/head에 대한 독립 PASS 후 PR 병합·main 포함·이슈 종료 확인까지다.
