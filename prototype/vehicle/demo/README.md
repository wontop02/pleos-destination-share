# 이 Mac의 Pleos 원클릭 데모

저장소 루트의 **`Pleos 데모 실행.command`**를 Finder에서 연다. 실행 위치나 경로의 공백에 영향받지 않으며, 이 파일을 가리키는 프로젝트 상위 폴더의 심볼릭 링크도 사용할 수 있다. 두 차량이 준비됐다는 문구가 나온 뒤 열린 차량 앱에서 이어서 사용한다.

현재 Mac 전용이다. Python 표준 라이브러리와 이미 승인·설치된 Node, Android SDK, 두 Pleos AVD 및 차량 APK를 사용한다. 도구를 내려받거나 APK를 설치하지 않는다.

## 로컬 설정

실제 설정은 기본 Git 저장소의 **`.harness/demo/config.json`**이다. worktree들도 같은 설정·잠금·상태·로그를 사용한다. `git rev-parse --git-common-dir`로 기본 저장소를 찾는다. 필요한 경우 `PLEOS_DEMO_HOME`에 별도 로컬 디렉터리의 절대 경로를 지정할 수 있다. 이 값은 실행끼리 같게 유지한다.

최초 준비 담당자는 [config.example.json](config.example.json)을 복사하고 절대 경로를 채운다. 현재 Mac에서는 기존 전용 환경의 값을 지정한 실제 설정을 사용한다. 예제 파일 자체는 실행 설정이 아니다.

| 항목 | 의미 |
|---|---|
| `version` | `1` |
| `repo_root` | 실행 파일이 있는 소스 checkout의 절대 경로 |
| `sdk_root`, `adb_metadata` | 기존 승인 toolchain SDK와 `owned-adb-server.json`의 절대 경로 |
| `node` | 기존 Node 실행 경로. 이 Mac은 `/opt/homebrew/bin/node` |
| `server.script`, `server.sha256` | 이 checkout의 `prototype/server.mjs` 및 승인 SHA-256 |
| `server.adopt_pid`, `server.adopt_started`, `server.adopt_script` | 기존 4192 서버를 처음 인계받을 때 함께 지정. 실제 PID·시작 시각·실행 파일·명령·소스 해시·loopback 포트를 검증한다. 시작 시각은 `LC_ALL=C`와 Mac의 현지 시간대에서 `ps -p PID -o lstart=`로 얻은 값이다. 이미 종료됐다면 빈 포트에서 새 서버를 시작한다. |
| `apk_sha256` | 두 차량에 이미 설치된 승인 APK의 SHA-256 |
| `emulators` | `Pleos12Leader:5570`, `Pleos12Follower:5572`, 각각 사용자 `10`, 실제 앱 pane `[853,90,2535,1300]` |
| `timeouts` | 선택적 단계별 초 단위 상한. 기본값은 명령 15, 서버 20, ADB 20, 차량별 부팅 240, 앱 화면 60. 각 값 1–600 |

설정에 토큰·초대 비밀·발화·키 내용을 넣지 않는다. 기존 ADB 메타데이터에서는 승인된 환경과 키 **경로**만 사용하며 키 파일을 읽거나 출력하지 않는다. 설정·상태·로그는 Git에 넣지 않는다.

실제 자원에 접근하지 않고 설정만 검사할 수 있다.

```sh
'/absolute/path/to/pleos-destination-share/Pleos 데모 실행.command' --check-config
```

## 실행과 보존

실행과 실패 상태 저장은 OS 파일 잠금 하나 안에서 처리한다. 먼저 실행 중인 창이 있으면 새 실행은 코드 `3`으로 끝난다. 이전 프로세스가 끝나면 파일이 남아 있어도 OS 잠금이 해제되므로 다시 실행할 수 있다. 잠금 파일을 지울 필요가 없다.

서버는 loopback 4192의 실제 실행 파일·PID·시작 시각·명령·소스 해시를 확인해 재사용한다. 빈 포트일 때만 이 checkout의 서버를 시작한다. 기존 방을 만들거나 지우지 않는다. 다른 서버의 포트는 종료하거나 덮어쓰지 않는다.

전용 ADB는 5041만 사용한다. 새 ADB가 필요하면 기존 승인 환경의 주소 override `ADB_SERVER_SOCKET`·`ANDROID_ADB_SERVER_PORT` 두 개만 시작용 복사본에서 빼고, 로컬 `-L tcp:5041`, mDNS 자동 연결 차단과 일치할 수 없는 USB allowlist로 시작한다. 시작 뒤 실제 loopback 수신과 실행 파일·격리 인자를 다시 확인한다. 이후 클라이언트는 원래 승인 환경을 유지한다. 차량 명령은 `-H 127.0.0.1 -P 5041 -s emulator-5570|emulator-5572`로 한정하며, ADB 5037이나 물리 기기를 사용하지 않는다.

차량은 승인된 SDK 실행 파일·포트·AVD 이름을 함께 확인한다. 꺼진 차량은 기존 데이터와 `-no-snapshot`으로 부팅한다. 부팅 완료, 전경 사용자 10, `am get-started-user-state 10`의 `RUNNING_UNLOCKED`를 확인한다. cold boot에서 시스템 사용자 0이 잠시 보이면 사용자 10을 유한하게 기다리며 사용자를 바꾸지 않는다. 새로 켠 차량은 이미 승인된 host microphone 연결만 복구하며 녹음을 시작하지 않는다.

각 차량의 `4182 → 4192`, `4192 → 4192` reverse 연결은 매번 검사한다. 빠진 연결만 `--no-rebind`로 만든다. 다른 목적지의 기존 연결이 있으면 실패한다. 앱의 주소·인증·방 저장은 수정하지 않는다.

설치 APK 해시가 다르거나 없으면 설치 없이 중단한다. 이미 한 개의 MainActivity와 정상 pane의 공개 제품 화면이 보이면 그대로 둔다. 열어야 할 때는 `MAIN/LAUNCHER`, `NEW_TASK | RESET_TASK_IF_NEEDED`, `--windowingMode 6 --display 0`으로 연다. 이미 열린 앱의 작성·설정 페이지를 강제로 홈으로 보내지 않는다. 앱 프로세스를 새로 시작하면 앱의 기본 화면으로 열린다. 실제 resumed MainActivity 한 개와 pane 안의 제품 페이지 View ID가 있어야 준비로 판단한다. PID나 HTTP 응답만으로 전체 성공을 표시하지 않는다. 부팅 직후 순정 내비가 전면을 가져가면, 같은 사용자에서 기존 MainActivity 한 개가 전경이 아닐 때만 3초 이상 간격으로 총 3회까지 같은 앱 진입을 요청한다. 실패하거나 시간이 초과된 진입 요청도 이 횟수에 포함한다. 원래 준비 기한을 연장하지 않으며, 이미 전경인 앱에 제품 페이지가 없으면 대화상자를 보존하고 재진입하지 않는다.

설치, 권한 부여, wipe, snapshot 복원, vendor 강제 종료, 전역 설정 변경, 음성 인식·제안·경로 요청·방 관리는 실행하지 않는다.

## 실패와 기록

창에는 쉬운 한국어 단계와 로그 경로만 표시한다. `.harness/demo/logs/*.jsonl`에는 단계, 종료 코드, 미리 정의한 실패 문구·예외 종류, 자원 PID·해시와 공개 페이지 종류 같은 제한된 상태만 남긴다. subprocess 원문, UI XML·텍스트·화면, 인증·초대·원음, 환경 값은 기록하지 않는다. `resources.json`은 소스 HEAD·런처/서버/APK 해시, 검증한 프로세스의 PID·시작 시각·실행 파일·명령 해시와 최근 준비 상태다. 실제 실행한 런처는 파일 해시로 별도 고정한다. 실패 뒤 일부 자원이 켜져 있어도 전체 상태를 `ready`로 쓰지 않는다.

| 종료 코드 | 대응 |
|---|---|
| `0` | 두 실제 앱 화면 준비 완료. `--check-config`에서는 설정 검사만 완료 |
| `2` | 누락·잘못된 설정 또는 로컬 기록. 예제와 경로·해시 확인 |
| `3` | 다른 실행이 준비 중. 먼저 연 창 확인 |
| `4` | 포트·프로세스·AVD·사용자 충돌. 기존 자원을 보존한 채 중단 |
| `5` | 유한 대기 시간 초과. 로그의 실패 단계와 차량 창 확인 후 재실행 |
| `6` | 도구 실행 실패. 해당 단계와 로컬 도구 경로 확인 |
| `7` | 설치 APK·연결·실제 앱 화면 확인 실패. 승인 APK와 권한·초대 창 및 차량 pane 확인 |

설정을 수정하기 전에 기존 로그를 보존한다. 소유권이 불명확한 프로세스나 충돌 포트를 해결하려고 런처가 종료 명령을 실행하지는 않는다.

## 격리 자동 검사

```sh
/usr/bin/python3 -m unittest discover -s prototype/vehicle/demo/tests -v
```

검사는 임시 디렉터리와 모의 Android 명령을 사용한다. 실제 `.command`의 다른 cwd·공백·심볼릭 링크와 macOS NFC/NFD 동일 파일 경로, 잘못된 설정, 동시 실행, 포트 충돌, PID 재사용, ADB 격리 인자, reverse 복구, 준비 timeout, 부팅 중 전경 이동 뒤 제한된 재진입, 대화상자 보존과 화면·중복 판정을 확인한다. 서버 cold-start 검사는 기존 4192를 건드리지 않고 OS가 배정한 별도 빈 포트의 **실제 Node 프로세스**를 시작하고 재사용한다. 정리는 그 검사에서 생성하고 신원을 재검증한 자식 프로세스에만 수행한다.

이 검사는 실제 두 차량의 warm/cold 실행·기존 방 복원과 별도 verifier의 판정을 대체하지 않는다. 실제 실행·화면·기존 자원 보존 증거와 정확한 base/head는 이번 이슈의 별도 검증 기록에 남긴다.
